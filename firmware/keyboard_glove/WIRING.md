# 결선도 및 핀 맵

`keyboard_glove.ino`가 전제하는 배선. 버튼을 추가·이동하거나 보드를 바꿀 때 이 문서를 먼저 갱신할 것.

## 배선 원리

모든 버튼은 `INPUT_PULLUP`으로 읽는다. 즉 **스위치 한쪽 다리는 지정 핀, 반대쪽은 GND**에 연결하고
외부 풀업 저항은 쓰지 않는다. 눌리지 않았을 때 핀은 내부 풀업으로 HIGH, 눌리면 GND와 통해 LOW가 된다.

```
        ATmega32u4
      ┌────────────┐
   D2 ┤            │
      └─────┬──────┘
            │
         ┌──┴──┐   택트 스위치 (6×6mm)
         │  ⌐  │
         └──┬──┘
            │
           GND
```

- 채터링은 펌웨어에서 `DEBOUNCE_MS = 30`으로 흡수하므로 하드웨어 디바운스 회로는 없다.
- 16개 스위치의 GND는 손별로 묶어 한 가닥으로 보드에 들어간다(배선 수 감소).

## 핀 맵 (코드 기준)

버튼 ID는 `손(L/R) + 손가락(1=검지 … 4=소지) + 마디(a=첫째, b=둘째)`, `5`는 기능키.
자모 배치는 [`mapping.json`](mapping.json)이 단일 출처다.

### 왼손 — 자음

| 버튼 | 핀 | 1탭 | 2연타 | 3연타 |
|---|---|---|---|---|
| L1a | D2 | ㄱ | ㅋ | ㄲ |
| L1b | D3 | ㅅ | ㅁ | ㅆ |
| L2a | D4 | ㄴ | ㄹ | — |
| L2b | D5 | ㅈ | ㅊ | ㅉ |
| L3a | D6 | ㄷ | ㅌ | ㄸ |
| L3b | D7 | ㅇ | ㅎ | — |
| L4 | D8 | ㅂ | ㅍ | ㅃ |
| L5 | D9 | Backspace | — | — |

### 오른손 — 모음

| 버튼 | 핀 | 1탭 | 2연타 | 3연타 |
|---|---|---|---|---|
| R1a | D10 | ㅓ | ㅕ | — |
| R1b | D11 | ㅗ | ㅛ | — |
| R2a | D12 | ㅏ | ㅑ | — |
| R2b | D13 | ㅜ | ㅠ | — |
| R3a | D14 | ㅐ | ㅒ | — |
| R3b | D15 | ㅣ | ㅡ | — |
| R4 | D16 | ㅔ | ㅖ | — |
| R5 | D17 | Space | . | Enter |

전송되는 키코드는 두벌식 QWERTY 대응값이며(예: ㄱ→`r`, ㅋ→`z`, ㄲ→`R`), 완성형 조합은 OS IME가 한다.

## ⚠ 확인 필요 — D14~D17의 실제 대응 핀

원본 스케치 주석은 이 네 개를 `R3a(A0), R3b(A1), R4(A2), R5(A3)`로 적어 두었다.
이 주석은 메카트로닉스 수업 때 쓴 최초 스케치에서 그대로 내려온 것으로,
[`legacy/sketch_nov28a.ino`](legacy/sketch_nov28a.ino)에서 원본을 확인할 수 있다
(레포의 첫 커밋 `0175b84`, 2025-11-28). 핀 번호 `{10 … 17}`은 그 스케치에서 손대지 않고
그대로 내려왔고, `A0~A3`라는 해석은 **원본 주석에만 남아 있다** — 현재 `keyboard_glove.ino`에는
그 주석이 없다. 즉 핀 번호는 계승됐는데 그 번호가 무엇을 가리키는지에 대한 근거는 검증 없이
사라진 상태다.

그런데 **A0~A3의 디지털 번호는 보드마다 다르다.**

| 보드 | A0 | A1 | A2 | A3 | D14~D17이 가리키는 것 |
|---|---|---|---|---|---|
| Uno | 14 | 15 | 16 | 17 | A0~A3 (주석과 일치) |
| **Leonardo** | **18** | **19** | **20** | **21** | MISO / SCK / MOSI / SS(RX LED) |

README는 보드를 Leonardo로 적고 있으므로, 코드의 `14~17`은 주석이 말하는 A0~A3이 아니라
**SPI 계열 핀**을 가리키게 된다. 특히 D17(SS)은 Leonardo에서 RX LED에 물려 있어 입력으로 쓰기에
적절하지 않고, 표준 Leonardo 보드에서는 헤더로 노출되지도 않는다.

실기기가 정상 동작하므로 셋 중 하나다:

1. 실제로는 A0~A3(**D18~D21**)에 배선되어 있고 코드의 핀 번호를 고쳐야 한다 → `R_PINS`의 뒤 네 개를 `{18, 19, 20, 21}`로 수정
2. ICSP 헤더의 SPI 핀에 직접 배선했다 → 현재 코드가 맞으나, D17(RX LED)에 물린 버튼(R5 = Space)의
   동작이 불안정하지 않은지 확인 필요
3. 핀 번호 체계가 다른 32u4 보드(Pro Micro 등)를 쓰고 있다 → README의 보드명을 정정

**확인 방법**: 보드를 연결하고 아래를 업로드해 각 버튼을 눌러 보면 어느 핀이 실제로 반응하는지 알 수 있다.

```cpp
void setup() {
  Serial.begin(115200);
  for (int p = 2; p <= 23; p++) pinMode(p, INPUT_PULLUP);
}
void loop() {
  for (int p = 2; p <= 23; p++)
    if (digitalRead(p) == LOW) { Serial.print("LOW: D"); Serial.println(p); }
  delay(150);
}
```

확인 결과에 맞춰 이 표와 `R_PINS`를 함께 고칠 것. 원본 스케치는 기록으로 남기는 파일이므로
고치지 않는다 — 수정은 `keyboard_glove.ino`에만 한다.

## 업로드

Arduino IDE에서 보드를 **Arduino Leonardo**로 선택하고 `keyboard_glove.ino`를 업로드한다.
업로드 직후 3초 지연(`delay(3000)`)은 Leonardo의 USB HID 열거가 끝나기를 기다리는 구간이라
그 사이 키 입력이 나가지 않는 것이 정상이다.

업로드된 펌웨어는 시리얼 115200 baud로 다음 명령을 받는다.

| 명령 | 동작 |
|---|---|
| `W<ms>` | 연타 판정 윈도우 설정 (100~600) |
| `S` | 현재 값을 EEPROM에 저장 |
| `R1` / `R0` | raw-tap 모드 on/off (캘리브레이션 측정용) |
| `C1` / `C0` | 탭 타임스탬프 스트림 on/off |
| `?` | 현재 윈도우·스탬프·raw 상태 출력 |

## 하드웨어 없이 로직 검증

핀 배선을 바꾸기 전후로 연타 엔진이 깨지지 않았는지 보드 없이 확인할 수 있다.

```bash
make -C test both
```

Arduino API를 스텁으로 대체하고 스케치를 그대로 `#include` 해 가상 시계로 구동하므로,
로직을 따로 옮겨 적지 않아 펌웨어와 테스트가 어긋나지 않는다.
